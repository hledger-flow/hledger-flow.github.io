Part 3: A difficult statement

This is the third part of a five-part tutorial. It continues in my-finances from part 2.

Bogart Bank

Section titled “Bogart Bank”

Gawie’s salary is paid into his cheque account at Bogart Bank. Bogart’s statement export hasn’t changed since the last century.

No draft this time. Gawie looks at the statement:

The first column says what kind of row it is, and only the 5 rows with a transaction number are transactions. The dates have Afrikaans month names and no year. The description is spread over three columns.

Gawie’s IT instincts say “write a script”. But each of these problems has an answer in hledger’s rules, and rules are easier to read, change and share than a script. He tries rules first.

Rules for a difficult CSV

Section titled “Rules for a difficult CSV”

Skip everything but transactions. skip inside an if block skips the matching rows. With !, the block matches rows that don’t match the pattern:

Name the columns. The fields line names every column. amount and balance are hledger field names: balance turns Bogart’s running balance into a balance assertion on every transaction, so hledger checks the arithmetic.

Rewrite the dates. An if table is a compact list of if blocks: each row has a pattern and the value to assign. In a value, \1 inserts what the pattern’s first parenthesised group matched, the day of the month here. hledger insists on a top-level date line, so Gawie starts with the raw date and lets the table replace it.

Build a description. hledger’s rules functions transform values as they’re used. join combines the three description columns, leaving out the empty ones, and replace removes Bogart’s stray #:

The cheque account brings new categories, which Gawie adds to import/gawie/categories.rules. If you skipped the exercise in part 2, add its answer too.

The payments to the credit card go to assets:transfers:creditcard, the account the card’s side of each payment already uses.

hledger-flow import regenerates every journal each time, so the card’s statements were imported again too. A change to a rules file always reaches every statement that uses it.

An opening balance

Section titled “An opening balance”

The balance assertion caught something. Bogart says the account held R40000 after the first transaction, but hledger only knows about the R500 fee. The account already had R40500 in it before the first statement.

hledger-flow includes a file named <year>-opening.journal in an account directory before that year’s statements. Gawie saves the opening balance as import/gawie/bogart/cheque/2016-opening.journal:

Gawie earns more than he spends every month, even in April, when the car needed new tyres. The card payments and investments don’t appear: they move money between Gawie’s own accounts, so they’re neither income nor expenses.

All from rules files, without a line of script. One thing still bothers Gawie: the year 2016 is written into his rules. That’s where part 4 begins.
